# B200 — NVIDIA Blackwell (SM100)

> Status: **prototype.** Highest peak performance but uTLX/Triton support for `tcgen05` and TMEM is beta as of early 2026.

## Hardware specs (verified)

| Spec | Value |
|---|---|
| Peak bf16 dense Tensor TF/s | ~2,250 (sustained ~1,800–2,000 under load due to clock throttling at >900 W) |
| Peak fp8 dense TF/s | ~4,500 |
| HBM3e bandwidth | 8.0 TB/s |
| L2 cache | 126 MB |
| SMEM / SM | 227 KB |
| TMEM / SM | 256 KB (new — accumulator-only, separate from SMEM) |
| Register file / SM | 256 KB |
| SMs | 148 |
| Tensor Core | 5th gen `tcgen05.mma`, supports 2-CTA pair MMA |
| Async copy | TMA + `tcgen05` async accum |
| TDP | 1000 W (SXM) — **sustained workloads can throttle**; cite 80% of peak |

## Roofline rebalance

| Region | FLOPs | Bytes | Peak ms | Realistic (60–75%) ms |
|---|---|---|---|---|
| S1 | 515 GFLOP | ~1.2 GB | 0.23 / 0.15 → **0.23** | 0.30–0.38 |
| Einsum | 274 GFLOP | ~537 MB | 0.122 / 0.067 → **0.122** | 0.16–0.20 |
| S3 | ~140 GFLOP | ~400 MB | 0.062 / 0.050 → **0.062** | 0.08–0.11 |
| **Total** | | | **~0.41 ms peak** | **~0.65–0.75 ms (tcgen05 ready) / ~0.85–0.95 ms (cuBLASLt fallback)** |

The model is **so small** on B200 that launch overhead (5 kernels × ~5 µs ≈ 25 µs) is 4–6% of e2e — **CUDA Graphs are mandatory** to amortize this and bring per-launch overhead to ~1 µs.

> Caveat: as with H100, the 1.2 GB / 400 MB IO numbers may be optimistic. If real S1 IO is closer to 2.68 GB (per H100 measurement), the B200 S1 mem time becomes 0.34 ms — still under compute time, but cuts the e2e improvement vs H100.

## Tile sizing recipe (227 KB SMEM + 256 KB TMEM)

**Einsum tile (tcgen05 2-CTA pair, BLOCK_M × BLOCK_N × BLOCK_K = 256 × 256 × 64):**
- Each CTA holds half the M dimension (128 rows of A, full N of B).
- A half: `128 × 64 × bf16 = 16 KB`; B: `256 × 64 × bf16 = 32 KB`.
- Per-stage AB: 48 KB; `num_stages=5–6`: 240–288 KB across the 2-CTA SMEM budget (~454 KB shared via DSMEM).
- **Accumulator lives in TMEM** (`256 × 256 × fp32 = 256 KB` per pair, exactly fits TMEM allocation).
- Frees SMEM for deeper pipelining and frees the register file for control flow.

## Specialization opportunities
- **`tcgen05.mma` + TMEM accumulator** is the headline feature — 2× FLOPs/cycle vs WGMMA when the accumulator doesn't have to round-trip through registers.
- **DSMEM across the 2-CTA cluster** is mandatory for the 2-CTA MMA shape.
- **fp8** still inadvisable for the same Cauchy-tail reason; bf16 is the practical target.

## Portability concerns
- **uTLX/Triton support for `tcgen05` and TMEM is beta as of early 2026.** Patch registry has experimental entries; expect lowering bugs on edge cases (non-aligned `K`, mask paths). **Strongly recommend benchmarking a cuBLASLt fallback** for S1 and a Triton WGMMA-style einsum tile (the H100 recipe scaled down) as the safe path.
- Power throttling: cite **80% of peak** in any presented numbers.
- **utlx wheel is NVIDIA-only**: B200 enabling needs the wheel to land sm100 codegen — not a portability problem, but does mean the same wheel build serves both H100 and B200.

## Top-3 recommendations
1. **CUDA Graphs first** — sub-ms regime makes per-launch overhead the dominant cost.
2. Prototype the **tcgen05 2-CTA einsum** but keep a cuBLASLt + WGMMA fallback enabled by config flag; ship whichever is faster on the day.
3. End-to-end realistic estimate: **~0.65–0.75 ms (tcgen05 ready)** or **~0.85–0.95 ms (fallback path)**.
