# A100 — NVIDIA Ampere (SM80)

> Status: **legacy / low payoff**. Treat as verification target only.

## Hardware specs (verified)

| Spec | Value |
|---|---|
| Peak bf16/fp16 Tensor TF/s | 312 |
| Peak TF32 TF/s | 156 |
| HBM2e bandwidth | 2.0 TB/s |
| L2 cache | 40 MB |
| SMEM / SM (max dynamic) | 164 KB |
| Register file / SM | 256 KB (65,536 × 32-bit) |
| SMs | 108 |
| Tensor Core | 3rd gen (`mma.sync` m16n8k16 bf16) |
| Async copy | `cp.async` (no TMA, no `cp.async.bulk`) |
| TDP | 400 W (SXM) — no thermal-throttle concern at this workload |

## Roofline rebalance (largest shape, peak vs 60–75% realistic)

| Region | FLOPs | Bytes (fused) | Peak ms (compute / mem) | Realistic ms (60–75%) |
|---|---|---|---|---|
| S1 LN+5 proj | 515 GFLOP | ~1.2 GB | 1.65 / 0.60 → **1.65** (compute) | 2.2–2.7 |
| Einsum | 274 GFLOP | ~537 MB | 0.88 / 0.27 → **0.88** (compute, 1.8× over memory) | 1.2–1.5 |
| S3 gate+proj | ~140 GFLOP | ~400 MB | 0.45 / 0.20 → **0.45** | 0.6–0.75 |
| **Total** | | | **~3.0 ms peak** | **~4.0–5.0 ms realistic** |

A100 is **compute-bound on every region** at `D=384`. At `D=128` the picture flips for S1/S3 (memory-bound) but einsum stays compute-bound.

> Caveat: H100 profile data showed S1 IO is closer to 2.68 GB than 1.2 GB. If A100 follows the same pattern, the S1 mem time becomes 1.34 ms — still under the 1.65 ms compute time, so A100's **compute-bound classification stands**, but the realistic e2e number may be 5.0+ ms.

## Tile sizing recipe (explicit byte budget, 164 KB SMEM cap)

**Einsum tile (BLOCK_I × BLOCK_J × BLOCK_K = 128 × 128 × 32):**
- `A` tile: `128 × 32 × bf16 = 8 KB`
- `B` tile: `128 × 32 × bf16 = 8 KB`
- Acc (fp32, register): `128 × 128 × 4 = 64 KB` — kept in registers, *not* SMEM
- Double-buffer A+B for `num_stages=3`: `(8 + 8) × 3 = 48 KB` SMEM
- Fits comfortably in 164 KB; leaves room for 2 CTAs/SM.
- `num_warps=8`, 3rd-gen `mma.sync` instructions, `cp.async` for prefetch.

**B+C-fused projection tile** (only viable at very small block sizes here):
- A 16×16 fused tile would require ~128 KB for the H-vector intermediate; doesn't double-buffer in 164 KB.
- Single-buffered 16×16 *or* an 8×8 tile fits, but launch overhead / occupancy loss makes this a net loss on A100. **Skip B+C fusion on A100** (see [`README.md`](README.md#bc-fusion-per-gpu-verdict)).

## Specialization opportunities
- Use **cuBLASLt for S1 projections** — empirically ~300 TF/s achievable vs 60–70% of peak for hand-Triton on Ampere (~210 TF/s).
- 3rd-gen Tensor Core is bf16/tf32 only — **do not attempt fp8** on A100 anyway, but worth noting that even if you were tempted, A100 has no fp8 path.
- `cp.async` (no TMA) means producer/consumer warp-specialization is awkward; stick with conventional pipelined loops.

## Portability concerns
- **utlx wheel is NVIDIA-only and currently targets sm90+ codegen paths**; Ampere works but several uTLX features (warp-spec, named-barrier shims) are no-ops or take fallback paths. Validate kernel correctness end-to-end before benchmarking.
- No TMA → any `tlx.async_copy` patches assuming `cp.async.bulk` semantics fall back to `cp.async`.

## Top-3 recommendations
1. Replace S1 projections with **cuBLASLt** GEMM calls; keep einsum and S3 in Triton.
2. Tile einsum at **128×128×32, num_stages=3, num_warps=8**; avoid B+C fusion entirely.
3. End-to-end realistic estimate: **~4.0–4.5 ms**. A100 is the lowest-payoff target — treat as legacy/verification only.
